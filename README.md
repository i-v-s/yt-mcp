# yt-mcp

Stdio MCP-сервер на Rust для чтения данных YouTrack 2021.3 через REST API
`/api`. Позволяет искать и читать задачи, комментарии, связи, проекты,
пользовательские поля и скачивать вложения.

## Сборка и запуск

Нужен актуальный стабильный Rust с поддержкой edition 2024.

~~~bash
cargo build --release --locked
cp yt-mcp.example.toml yt-mcp.toml
chmod 600 yt-mcp.toml
~~~

Впишите постоянный токен YouTrack в `yt-mcp.toml`. Затем запускайте бинарный
файл из MCP-клиента:

~~~bash
./target/release/yt-mcp --config /absolute/path/to/yt-mcp.toml
~~~

Если `--config` не указан, сервер сначала ищет `yt-mcp.toml` в текущем
каталоге, затем `~/.config/yt-mcp.toml`. Явно указанный путь имеет приоритет.
Если выбранный файл существует, но некорректен или недоступен для чтения,
сервер сообщает ошибку и не переключается на другой конфиг.
Сервер не подключается к YouTrack при старте: проверить соединение можно инструментом
`get_current_user`. В stdin/stdout передаются только сообщения MCP;
диагностика выводится в stderr. EOF завершает сервер.

## Конфигурация

Настройки читаются только из TOML-файла при запуске. Переменные окружения
не переопределяют настройки.

~~~toml
url = "https://youtrack.com"
token = "perm:YOUR_TOKEN"
download_dir = "./downloads"
timeout_secs = 60
max_attachment_bytes = 104857600
~~~

| Поле | Значение по умолчанию | Описание |
|---|---|---|
| `url` | `https://youtrack.com` | Базовый URL без `/api`; поддерживается путь вроде `https://host/youtrack` |
| `token` | нет, обязательно | Постоянный токен со scope YouTrack |
| `download_dir` | `./downloads` | Относительный путь считается от каталога файла конфигурации |
| `timeout_secs` | `60` | Тайм-аут HTTP-запроса, включая чтение тела; от 1 до 3600 секунд |
| `max_attachment_bytes` | `104857600` | Максимальный размер одного скачиваемого вложения, 100 МиБ |

Скопированный пример требует замены `perm:YOUR_TOKEN`. Отсутствующий файл,
неизвестные поля, неверные типы или значения настроек приводят к ошибке
запуска. Конфигурация и токен не выводятся в диагностику.
Рабочий `yt-mcp.toml`, `downloads/` и `target/` исключены из Git.

Пример конфигурации клиента, поддерживающего `mcpServers`:

~~~json
{
  "mcpServers": {
    "youtrack": {
      "command": "/absolute/path/to/yt-mcp/target/release/yt-mcp",
      "args": ["--config", "/absolute/path/to/yt-mcp.toml"]
    }
  }
}
~~~

## Доступ только на чтение

HTTP-клиент отправляет только GET-запросы по фиксированным маршрутам.
Инструментов создания, изменения, удаления данных или произвольных
HTTP-запросов нет. Сервер использует права и ограничения видимости
владельца токена.

Для ограничения доступа также на стороне YouTrack используйте отдельную
учётную запись с правами чтения нужных проектов, задач и комментариев.
Для закрытых пользовательских полей могут понадобиться дополнительные
права чтения. Scope постоянного токена выбирает сервис; права на
операции определяются правами учётной записи.
См. [Permanent Token Authorization](https://www.jetbrains.com/help/youtrack/devportal/authentication-with-permanent-token.html).

Девять инструментов чтения имеют аннотацию MCP `readOnlyHint=true`.
`download_attachment` имеет `readOnlyHint=false`, `destructiveHint=false`
и `idempotentHint=false`: он читает YouTrack, но каждый раз создаёт новый
локальный файл.

## Инструменты

| Инструмент | Аргументы | Результат |
|---|---|---|
| `get_current_user` | нет | ID, login, полное имя и признак гостя |
| `search_issues` | `query`, `limit?`, `offset?` | Поиск задач с пользовательскими полями |
| `get_issue` | `issue_id` | Описание, проект, автор, теги и значения пользовательских полей |
| `list_issue_comments` | `issue_id`, `limit?`, `offset?` | Комментарии, авторы, даты и метаданные вложений |
| `list_issue_links` | `issue_id`, `limit?`, `offset?` | ID, типы и направления связей |
| `list_linked_issues` | `issue_id`, `link_id`, `limit?`, `offset?` | Задачи по выбранной связи |
| `list_projects` | `limit?`, `offset?` | ID, названия, префиксы и описания проектов |
| `list_project_fields` | `project_id`, `limit?`, `offset?` | Названия, типы и настройки полей проекта |
| `list_issue_attachments` | `issue_id`, `limit?`, `offset?` | ID, имена, размеры и MIME-типы вложений |
| `download_attachment` | `issue_id`, `attachment_id` | Абсолютный локальный путь, исходное имя, фактический размер и MIME-тип |

Задачи принимаются по ключу (`PROJECT-123`) или внутреннему ID (`2-42`).
`project_id` — внутренний ID из `list_projects`, например `0-1`.
`link_id` берётся из `list_issue_links`, `attachment_id` — из списка
вложений или комментария.

Результаты возвращаются как JSON в текстовом содержимом ответа MCP.
Поля YouTrack сохраняют исходные типы значений, включая `null`,
числа, строки, объекты пользователей и массивы значений.
Даты представлены Unix timestamp в миллисекундах.

Списки используют `limit` (по умолчанию 20, от 1 до 100) и `offset`
(по умолчанию 0). Пример:

~~~json
{
  "items": [{"id": "2-42", "idReadable": "PROJECT-123", "summary": "Пример"}],
  "limit": 20,
  "offset": 0,
  "count": 1,
  "next_offset": 1
}
~~~

Передавайте `next_offset` в следующий запрос, пока не получите пустую
страницу с `next_offset=null`. Короткая страница тоже получает
`next_offset`, поскольку YouTrack может ограничивать размер ответа своими
настройками. Пагинация не является снимком: при изменениях в YouTrack
между запросами возможны повторы и пропуски.

`query` использует язык поиска YouTrack:

~~~text
for: me #Unresolved sort by: updated desc
project: {Название проекта} State: Open
~~~

Пустая строка означает все доступные задачи. Комментарии, связи и
вложения читаются отдельными инструментами, чтобы не терять элементы
вложенных коллекций из-за ограничений пагинации.
JSON-ответ REST API ограничен 16 МиБ; для больших ответов уменьшите `limit`.

## Вложения

Сервер сначала запрашивает метаданные конкретного вложения, затем читает
его URL. Абсолютные и относительные URL поддерживаются; переход на другой
origin, включая смену схемы или порта, запрещён. Подписанные URL не
включаются в диагностику.

Каталог загрузок создаётся при первой загрузке. Файл получает уникальный
префикс и безопасное исходное имя, например `yt-abc123-отчёт.pdf`.
Имя из YouTrack не может вывести запись за пределы настроенного каталога.
Существующие файлы не перезаписываются. Повторное скачивание создаёт
отдельный файл.

Лимит размера проверяется по метаданным, Content-Length и фактически
полученным байтам. При ошибке, тайм-ауте или отмене запроса MCP частичный
файл удаляется. Файлы не исполняются и не разбираются сервером.

## Проверки

Для тестов нужны Python 3 и возможность открывать локальные loopback-сокеты.
Smoke-тест настоящего бинарного файла также автоматически входит в
`cargo test`.

Проверку реального YouTrack с автоматически найденным конфигом можно
запустить отдельно; она выполняет только чтение, без скачивания файлов:

~~~bash
cargo test --offline --locked live_configured_youtrack -- --ignored --nocapture
~~~

~~~bash
cargo fmt --check
cargo clippy --offline --all-targets -- -D warnings
cargo test --offline --locked
cargo build --offline --locked
python3 scripts/smoke_test.py --binary target/debug/yt-mcp
~~~

Rust-тесты используют локальный HTTP-сервер: проверяются маршруты и GET,
авторизация, кодирование запросов, пагинация, типы полей, ошибки,
скачивание, ограничения размера, редиректы и очистка файлов.
Smoke-тест запускает настоящий бинарный файл через stdio с временной
конфигурацией и локальным HTTP-сервером.

Для проверки на установленном YouTrack подключите MCP-клиент с рабочей
конфигурацией и вызовите `get_current_user`, затем `list_projects`,
`search_issues`, `get_issue` и загрузку доступного вложения.

История изменений, трудозатраты, статьи базы знаний и операции записи
в эту версию не входят.

Справочник API: [YouTrack REST API](https://www.jetbrains.com/help/youtrack/devportal/youtrack-rest-api.html).
